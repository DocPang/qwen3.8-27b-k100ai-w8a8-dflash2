# 精度调查：冻结候选在 GSM8K 上不通过，根因定位到**投机解码路径**

> 这是本次封版最重要的发现。结论先行：
> **同一份权重、同一套调优表、同一台机器，关掉投机解码后 GSM8K 由 ~10% 变成 93.3%（n=150）。**
> 因此精度失败**不是** W8A8 量化、**不是**任何 overlay 臂，而是 **DFLASH 投机路径**（草稿/验证）造成的输出损坏。

---

## 1. 问题

按项目准入规则（GSM8K ≥ 95.0）对冻结候选做检查时，结果远低于门槛。

评测口径（三轮实验统一）：`modelscope/gsm8k` test split，0-shot，greedy，
`chat_template_kwargs {"enable_thinking": false}`，`max_tokens=1024`，并发 4–8。

---

## 2. 受控实验矩阵（全部在同一台 2×K100AI 主机、同一份官方 W8A8 权重上）

| # | 车道 | 投机 | overlay 链 | W8A8 调优表 | GSM8K | 输出形态 |
|---|---|---|---|---|---|---|
| A | **冻结候选** `q38-official-contest-hcu23-20261017` | **DFLASH ON** | 全 11 臂 | 308 表 | **10.4%（n=414，全量仍在跑）** | 文本连贯，但**算术损坏**（`160+80+20=80`、`9×2=12`、`400+54=50`） |
| B | 对照 `q38-q8only-hcu45-20261017` | **DFLASH ON** | 仅链根（`batch2_raw_q8_overlay`） | 308 表 | **12.5%（n=8）** | 同上 |
| C | 对照 `q38-nospec-hcu45-20261017` | **NONE（关闭）** | 仅链根 | 308 表 | **93.3%（n=150）**（前 60 题曾达 96.7%） | **算术正确**（`9×$2=$18`、`180×3=540`、`2+1=3`） |
| D | 对照 `q38-stock-control` | DFLASH ON | 关 | 关 | 退化（重复垃圾 token） | `vdrvdrvdrv…` 直到 max_tokens |
| E | 对照 `q38-tablesonly-…` | DFLASH ON | 关 | 308 表 | 退化（重复垃圾 token） | 同上 |

> A 与 B 的差异是"优化臂"，两者精度几乎相同 ⇒ **优化臂无罪**。
> B 与 C 的差异**只有投机开关这一个变量** ⇒ **投机路径有罪**。
> D/E 说明"关掉 overlay 链"会得到一个**完全不可用**的栈（重复垃圾），
> 即：overlay 链在本栈里同时承担**正确性**职责，不只是性能。

### 2.1 "算术损坏"是什么样的

模型推理步骤本身往往是对的，坏在**最后一步算术**：

```text
160 + 80 + 20 = 80            (gold 260)
9 eggs × $2/egg = 12 dollars  (gold $18)
$400 + $54 = $50              (gold $454)
```

这与"模型不会做题"不同：是**同一段文本里前后数字自相矛盾**，
典型的**生成 token 被错误替换**的形态。

### 2.2 与控制变量的排除

| 被排除的假设 | 证据 |
|---|---|
| 采样（greedy vs temp1.0/top_p0.95/top_k20） | 两种采样都出现同样的算术损坏 ⇒ 不是采样假象 |
| 思考模式太长导致空回答 | 那是另一个独立问题（§4）；本节的 12% 全部发生在**非思考模式、有完整回答**的情况下 |
| 回答抽取脚本 | 肉眼复核原文：模型**确实**输出了错误数字 |
| W8A8 量化本身 | 关掉投机后同一份 W8A8 权重给出 95–100% ⇒ 量化不是充分原因 |
| 优化 overlay 臂（FASTHEAD/CANDHEAD/…） | A vs B：臂全开与臂几乎全关，精度同为 ~12% |
| 调优表 | E（只有表、无链）反而是**更糟**的垃圾输出 ⇒ 表不是损坏来源（它反而是可用性前提之一） |

## 3. 结论与影响

1. **冻结候选（DFLASH ON）不满足精度准入**（10.4% vs 95.0），按项目规则**不得**作为最终参赛候选。
1b. **关掉投机的替代配置也只有 93.3%（n=150）**，仍低于 95.0 门槛约 1.7 个点
   （残余错误多为数值/抽取边界：`36 → 36.36`、`95200 → 99,076.92`、`60 → 5`）。
   即：**投机路径是主要元凶（−83 个点），但它不是唯一的精度缺口**。
   该替代配置的 harness 口径是 0-shot / greedy / `max_tokens=1024` / `enable_thinking=false`（公开等效预验证，非主办方最终口径）。
2. 根因落在 **DFLASH 投机路径**（草稿前向 / 验证 / KV 槽位分配），
   与项目既往记录中"投机路径引入行相关数值分歧（`in_diff` 1.36→5.67）"的方向一致
   （此前只被当作影响 accept 的**确定性**问题，本轮证明它同时是**正确性**问题）。
3. **C1 逐位锁不能证明正确性**：冻结候选在 3/3 次复现下锁完全一致（determinism ✓），
   但每次复现的都是**同一段被损坏的输出**。这类"确定性错误"必须用**外部基准**才能发现——
   这是本次最重要的方法论教训。
4. 该发现同时解释了另两个悬案：
   * "真实长上下文工具会话下服务卡死"（`chunk_gated_delta_rule → prepare_chunk_indices`）；
   * "思考模式下回答为空/语义混乱"（§4）。
   三者都指向同一段投机/草稿路径。

---

## 4. 附带发现：思考模式的 harness 陷阱

本 checkpoint 自带的 chat 模板把 `reasoning_effort` 默认值设为 **`xhigh`**
（"think carefully … consider plausible alternatives"）。在 `max_tokens=4096` 下：

* 多数 GSM8K 题目的**全部** 4096 个 token 都花在思考流上，`content` 为空、`finish_reason=length`
  ⇒ 记 0 分（**harness 口径问题，不是模型不会**）。
* 因此本仓库所有精度运行都显式传 `chat_template_kwargs.enable_thinking=false`，
  并在报告里注明该模式。

写这一节是为了让复现者不要重踩：**同一个候选在 1024/4096 token 预算、思考开/关下分数完全不同**，
报告里必须写明用的是哪一种。

---

## 5. 建议的下一步（按性价比）

1. **定位投机路径的具体缺陷**：在 `batch2_raw_q8_overlay` 关闭/开启之间做二分，
   并在验证步 dump 草稿输入/输出（项目已有 `chainprobe`/`specprobe` 仪器）。
2. **短期可交付的替代候选**：关掉投机（`SWEEP_SPEC_ALGO=NONE`）+ 保留非投机类优化
   （调优表、FASTHEAD、GDNFUSE、PREFILL_GDN、ATTNCFG）。
   代价是吞吐显著下降（本仓库同时给出该配置的官方协议对比，见 `docs/RESULTS_OFFICIAL.md` §6）。
   注意它当前是 93.3%，仍差 1.7 个点：需要先确认口径（是否应给思考模式更大 token 预算），再谈提交。
3. 若比赛只承认带投机的性能数字，则必须先把投机路径修到精度门通过再提交。
